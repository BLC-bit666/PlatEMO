# PairGuide 核心机制审查请求

你是一名约束多目标优化、进化计算与生成模型专家。请以附件中的**当前源码、实验脚本、CSV/MAT 数据和图片**为证据，深入审查当前实验主线 `PairGuide`，找出根因并设计一套完整、最小、可验证的改进方案。本轮只分析和设计，不改代码。

先查证，后结论。必须区分代码事实、实验事实和推断。本提示优先级最高；附件文档仅描述当前实现，不代表其中每项机制都已确认正确。

## 三个核心目标

1. **生成窄边界带**：CGAN 生成分布应集中在真实 `xf-xi` 之间、靠近真实约束边界的窄带，而不是厚点云、端点云或仅靠近 `xi` 的云。
2. **高频且有效使用**：模型不只是频繁训练或前向查询，而要经常产生可完整评价、可进入搜索流程、可收紧 pair 的有效子代，显著降低 PairGuide 名额被普通 DE 回填的比例。
3. **加速 P1 搜索边界**：在相同 FE 下，生成子代应真实引导约束种群 P1 更早、更稳定、更广泛地逼近有价值的约束边界，并进一步改善收敛和分布。

生成点是否可行不是单独成败标准。核心是边界距离、pair gap 收紧、有效使用频率及对 P1 搜索速度的因果贡献。三个目标必须同时满足，不能只优化网络损失或点云外观。

## 当前实验

- 问题：LIRCMOP5_BC、7_BC、8_BC、10_BC、12_BC。
- 每题 5 次；`N=100`；`FE=100000`；维度采用问题默认值 `D=30`。
- 当前设置：训练 `Sigma=1`，推理 `sampleSigma=0.3`，10 worker。
- 25/25 次运行完成；run 1 保存阶段图，其余运行用于数值统计。

## 必须审查的问题

1. **尚无证据证明 PairGuide 加速了 P1。**当前实验没有同种子、同 FE 的 fallback-only/禁用 CGAN 对照。P1 在全部 250 个检查点都有 100 个可行解，但这不能说明它靠近边界，也不能证明 CGAN 优于普通 DE。

2. **生成分布没有形成窄边界带。**2,540,000 个 raw 点中，仅 13,111 个进入 matched pair 闭球，比例 0.516%；图中仍是明显厚点云。当前只查询 `side=0`，训练目标是端点，生成目标却是两端之间的边界带。请核验 thickness、matched pair gap、到端点线段的轴向位置和垂直距离，不能只看二维图或可行率。

3. **模型几乎没有实际承担 PairGuide 配额。**全部运行共有 248,194 个名义引导名额，仅选中 901 个 CGAN 子代，实际填充率 0.363%；247,293 个名额由普通 DE 回填，回填率 99.637%。12,418 个 use 事件中，仅 760 个事件至少产生 1 个引导子代；LIRCMOP10/12 从未训练或使用模型。高频训练不等于高频有效使用。

4. **边界更新贡献极低。**901 个完整评价引导子代只带来 59 次 pair 收紧，比例 6.55%；全部为 `xi` 收紧，`xf` 为 0，且只发生在 LIRCMOP5/7/8。全算法共有 30,982 次 `xf` 收紧和 7,647 次 `xi` 收紧，CGAN 归因仅 59 次，约占总收紧的 0.153%。必须判断 CGAN 是否真正推动训练集演化，而不是旁观普通搜索完成边界构造。

5. **32-pair 统一门槛阻断训练和复用。**首次训练、继续使用及重训共用 32 个不同方向 active pair 的门槛。达到 12/16/24/32 对的运行数分别为 25/22/20/15；LIRCMOP10/12 五次运行全部未训练。LIRCMOP5 首训后 active pair 可降至 3–7，模型随之停用。32 不是网络结构必需条件，代码支持小尾批。

6. **pair 档案高周转、低稳定存量。**累计新建 553,022 个 pair，但部分问题 active pair 长期不足 32。当前合法性、历史 `xf/xi`、参考归属、失活、恢复、删除和 ID 策略可能制造虚假变化、丢失仍有价值的端点并使训练集高度非平稳。需要逐条审查，而不是默认当前生命周期正确。

7. **重训成本极高，边际收益未知。**15 次首次训练后发生 5,065 次 warm-start 重训，中位间隔约 200 FE；训练约耗时 6.545 小时，占总 worker 墙钟约 92.8%。需要按模型版本验证每次重训是否提高入带率、入选率、pair 收紧率及 P1 边界搜索速度，并区分过拟合、灾难性遗忘和训练集漂移。

8. **生成筛选与接入链路可能偏离边界目标。**当前链路为 `side=0` 生成、matched-pair 闭球、objective-only 走廊、当前 P1 父代匹配、`u=0.5(c+G)` 二次映射、完整评价。每一步都可能淘汰边界候选或破坏其原 pair 几何归属。请做逐级归因，不要预设任一步必须保留。

9. **现有指标不足以回答核心目标。**IGD/HV、可行率和训练损失不能直接衡量窄边界带、高频有效使用或 P1 到边界的速度。需要补充可计算的边界几何、档案收紧、实际配额占用、P1 边界覆盖和同 FE 因果对照指标。

以上不是问题上限。若源码、数据或图片揭示其他关键问题，请补充并排序。

## 仅有的硬约束

1. 保持双种群基本框架：P1 做约束搜索，P2 做无约束搜索；二者从同一真实评价 Union 独立环境选择。
2. P1 固定为 25% GA、55% 普通 DE、20% PairGuide，缺额由同一路径普通 DE 回填；P2 固定为 25% GA、75% 普通 DE。
3. donor 在本代末生成，供下一代 P1 使用；不得改成同代即时使用。
4. pair 由真实完整评价的可行端 `xf` 与不可行端 `xi` 构成；真实评价反馈持续缩短 gap，以端点对作为逐步收窄的边界代理。每参考方向最多一个 active pair，pair 邻域总数固定为 5（含自身）。
5. CGAN 的训练表示固定为归一化真实绝对端点：

   \[
   [x_f^{norm},w,1],\qquad[x_i^{norm},w,0]
   \]

   同一 pair 两端使用同一个噪声 `z`。训练必须保留两端，不能改成只训练中点、伪边界点或未真实评价点。
6. 不得增加“raw `G` 不被任一当前可行精英支配”的全局过滤。该建议已明确否决。
7. 评价管线和 FE 记账方式不锁定。任何真实 `CalObj/CalCon` 调用及纯网络前向成本都必须分别、透明报告，并保证对照实验使用同一预算口径；不得把实际评价隐藏成零成本。是否保留 objective-only、是否直接完整评价、如何计入预算及评价后进入哪里，均可修改。
8. 保持 `PairGuide` 身份，不得通过名称映射把上一任算法整体换回；实验维度继续使用问题默认值，不手工设为 `D=20`。

除上述内容外，不得把当前实现误当成不可修改结论。

## 明确允许修改和重新设计

1. 历史 `xf/xi` 的保留、替换来源、合法性、迁移、失活、恢复与删除条件。
2. pair 失活后复用旧 ID 还是分配新 ID，以及 ID 是否仍适合训练集变化检测。
3. WGAN-GP 网络结构、损失函数、训练轮数、batch、优化器、正则化、附加网络、动态权重及统一或问题专用机制；但必须保留上述端点训练表示。
4. 训练 `Sigma`、推理 `sampleSigma` 及其调度。`1/0.3` 只是当前基线；`0.3` 曾表现较好，但尚未证明最优。
5. 首训、继续使用和重训的独立门槛；允许旧模型在训练集不足时继续服务，也允许设计可信的停用条件。
6. 同一 `(z,w)` 分别生成 `G_f=G(z,w,1)`、`G_i=G(z,w,0)` 后的插值、投影或其他区间生成方法；不得直接使用训练中不存在的 `side=0.5` 冒充已学习条件。
7. raw 数量、分配方式、球定义、`rho`、critic、排序、去重、目标走廊和筛选顺序。
8. `0.5(c+G)` 是否保留、是否直接完整评价生成候选、评价后的 archive/Union 接入与 PairGuide 配额使用方式。
9. objective-only 阶段、完整评价数量、FE 口径及评价成本分配。
10. 训练集实质变化度量、冷却间隔、验证集、早停、模型接受标准和旧模型复用。
11. 旧算法中的单个机制可以作为证据或候选重新评估，但不得不经论证地整体回退成上一任算法。问题专用机制允许讨论，但必须说明必要性、泛化风险和公平比较方式。
