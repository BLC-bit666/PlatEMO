## 调用与 FE

`Evaluation(X)` 先调用原生 `PROBLEM.CalDec` 进行边界修复，然后向 Python 评价器发送整批决策。每行按一次逻辑评价计入 FE，原样返回两个目标及一个标签，构造原生 `SOLUTION`。缓存命中同样计入 FE，不给算法额外搜索预算。不可行解照常保留原始目标。评价故障抛出异常，不转成罚值或约束标签。

Python 使用固定虚拟环境与 MATLAB `OutOfProcess` 接口，图像/地图对象在各问题对象内部复用。MATLAB 数组直接交给 Python 中的 `numpy.asarray`，避免重复的跨进程数组构造。`EvaluatorCalls()` 返回已完成请求数（含缓存命中），用于核对 FE；`EvaluatorStatistics()` 另行报告实际最短路求解、渲染及缓存命中数。直接调用 `CalObj` 或 `CalCon` 会单独发出评价请求，遵循 PlatEMO 中这些方法不增加 FE 的语义；优化算法应走合并后的 `Evaluation`。

### 骑行评价器的逐层复用

`Support/fast_route.py` 保留原公式的 float64 运算顺序，分层复用：

- 固定路面/道路权重、高程差、节点映射、CSR 结构和反向邻接索引只构建一次；节点对象与路段几何按需解析并复用。
- 边成本使用原生 C++ 单遍计算，保留原 float64 乘加顺序，关闭 fast-math 和 FMA。实测替换了逐参数缓存及多遍 NumPy 数组操作；不引入相近参数近似。并行边的最小代价只在确有并行边的组中更新。
- 每个请求先查精确 float64 决策缓存。新决策才求路；路线结果按**具体有向路段 ID 序列**缓存，不仅按节点序列缓存，避免平行道路混淆。平行边同价时保留原始表中最先出现的边，等价于作者 `_select_path_edges` 的严格小于比较。新路线仍调用作者原版 `build_track`，不把整条路线的高程重采样改成逐边爬升相加。
- 固定终点的 32 个参数角点各预计算一次反向最短距离，作为有证明的搜索下界。每个新解选择一个保守缩放下界，用原生 A* 缩小搜索范围；下界不改变最优解。检查目标路径每个节点的其他入边，若存在等价或接近浮点误差界的候选，退回作者原版无限制 SciPy 搜索，保留原有并列路径选择。没有把近似路线作为精确解。

决策、路径索引和路线结果三个 LRU 各最多 1024 项；测试时可用 `cache_size=0` 禁用这些结果缓存。节点和几何缓存最多覆盖固定图一次。缓存属于当前问题实例，不在独立实验之间共享。返回的可变列表重新创建，调用方修改返回值不会污染缓存。

每个独立进程使用自己的评价器对象，单个对象按顺序评价；不要在多个线程间共享同一实例的 CSR、代价缓冲区或缓存。适用 `parpool('Processes',10)`。MATLAB 算法、逻辑 FE 和原生指标不变。

第一轮验证记录在 `outputs/realapps_performance_audit_20261119/`。后续缓存验证记录在 `outputs/realapps_cache_optimization_20261119/`，包括完整路线、边代价/CSR、并列与近并列搜索回退、LRU 淘汰、返回值污染及两算法/两问题的原生 MATLAB 回归。原版 `route_problem.py`、作者代码、已停止实验和第一轮快照保留。

### 二维码识读的等价短路

实际 DRMCMO 初始化暴露了固定样例未覆盖的慢输入：seed=20261119 的第 32 个初始解，原尺寸识读已失败，第二项 180×180 缩小图却让 ZXing-C++ 长时间占用 CPU。独立 Python 与仅含该图像的最小回放也复现了超时，因此不是 MATLAB 数组传输故障。

只在我们自己的 `qr_problem.py` 增加可选 `short_circuit=False` 参数。默认仍完整执行原来的三项检查，原 88 组所有确定性输出保持一致。PlatEMO 接口传 `short_circuit=True`：任一检查实际失败后停止后续检查。`all(checks)` 已经为 false，因此标量约束必为 1；目标早已按原代码计算完成。没有把超时当作失败，没有降低识读要求，也没有修改解码选项。

快速模式的 `decoded_correctly` 只记录已实际执行的检查前缀；PlatEMO 仅接收两项目标和一个标量约束，二者与完整模式逐项核对一致。慢输入回归由超时变为约 0.17 秒完成；同一批 100 个初始解约 0.48 秒完成。具体输入、原始图、回归测试和完整实验状态见本次输出目录。

`Support/fast_qr.py` 进一步把缩图和模糊图改为按需生成：前项已失败并短路时，不再生成后续图像。它以原程序本来就使用的 16 个 float32 系数、JPEG 整数质量和检查模式作为缓存键，没有增加任何舍入。最多缓存 1024 份 JPEG、目标与真实识读结果；保存缓存命中的图像时直接写回相同 JPEG 字节。完整检查与短路检查使用不同键，保持 `decoded_correctly` 的含义。原 `qr_problem.py` 保留不动。

### 2026-11-20 等效性能优化与解码稳定性修复

`Support/native/` 保存原生源码、本机库、许可证和构建说明。骑行替换多遍代价数组计算和无目标的广域搜索；二维码将原始混合图计算与 MSE 的等效整数求和放到 C++，JPEG 编解码、缩图、模糊和实际识读条件不变。32 个路线下界只在问题对象初始化时计算，初始化耗时与每解耗时分开报告。

ZXing-C++ 3.1.1 的 `TraceLine` 仍可能接收到两个重合定位点，方向归一化出现 NaN，随后整数方向成为零，循环中的后退不再移动。局部补丁在该几何状态下返回无效追踪线，继续原先已有的几何回退和解码；没有使用超时罚值、跳过识读条件或改变解码选项。保持原安装包与历史冻结实验不变，仅当前适配器使用局部构建。普通已终止输入精确一致；旧版永不终止的输入没有可比较的旧标签，修复后由实际解码结果决定标签。

新 C 接口明确声明 RGB，避免把 RGB NumPy 数组交给默认按 BGR 解释的 Python 接口。任何其他评价异常仍抛出，不能伪造约束或目标。

证据与完整报告：`outputs/realapps_performance_diagnosis_20261120/REPORT.md`。包括正常输入目标/标签/JPEG/路线一致性、40,000 次历史评价回放、精确并列回退、实际卡顿输入回归、MATLAB FE/RNG 检查及 10 进程吞吐测试。正式实验仍由用户暂停；历史运行目录和已完成结果未更新。

## 指标

HV 严格调用 `PROBLEM.CalMetric` / `Metrics/HV.m`。`GetOptimum` 的两个固定数来自优化运行前已存在的验证样例，见 `Support/reference_bounds.json`：

- 二维码：`[40958, 12995.966327160493]`。
- 骑行：`[51.77148668090174, 1596.6355452601128]`。

这只是本轮运行验证的统一 HV 参考尺度，**不是已知 Pareto 前沿，也不是全决策域目标上界**。原生 HV 自行使用可行非支配解、进行归一化、应用 1.1 系数并计算二维精确 HV。未对送入算法的目标值做归一化。不同算法/种子比较必须保持这份参考尺度一致；若正式实验另定尺度，所有结果须统一重算，不能混用。

其他指标直接调用 PlatEMO 原函数，并传空 PF。`Feasible_rate` 正常计算，`IGD/GD` 保持缺参考前沿时的原生 NaN 行为；没有把一个 HV 参考点冒充 PF。没有可行非支配解时，保留当前原生 HV 的 NaN。
